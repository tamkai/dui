# DUI — DOGA UI

CLI（文字を打つ）→ GUI（画面を押す）→ **DUI（AI が動画で聞き、人は押すか話すだけ）**。

目的は、人が大量の文字を読む負担を減らし、状況を理解して判断できるようにすること。動画の本数や豪華さを目標にしない。

## 流れ
1. **動画で聞く**: 判断の分かれ目で、30 秒前後の声つき動画を 1 本作る。1 本に判断は 1 つ、60 秒以内
2. **押す / 話す**: 動画の下に選択肢のボタンを付ける。追加の注文は、人が音声入力で自由に話す
3. **聞き返す**: 話した内容は長くても整理を頼まない。AI が意図を拾い、「つまりこういうこと？」を短い確認動画で返す
4. **動く**: 押された選択の範囲だけ実行する。結果も、必要なら次の短い動画で返す

## 台本を作る
- 構成は `references/script-types.md` の場面の型 8 種（題名・一言・状況・比較・数字・手順・流れ図・問い）で台本 JSON にする。最後は必ず `question`
- 書いたら `python3 scripts/check_script.py < script.json` で検査する（標準ライブラリだけで動く）
- `say`（ナレーション）は 1 場面 1〜2 文、1 文 40 字以内、8 字以上。英字・略語は片仮名で書く（TTS が英字を読み違える）。画面の文字は英字のままでよい
- 決定・提案・未確認を混ぜない。毎回ぜんぶ説明し直さず、変わった所を中心に伝える

## 動画にする（確認用動画）
- `tool/make_confirm.py <script.json>` で作る。検査 → 絵（Pillow）と声（Irodori-TTS）を並列 → 発話ごとに faster-whisper で原稿と照合し、ずれた発話だけ作り直す（最大 2 回）→ mp4（1280x720、1MB 前後）
- 目安: 4 場面で約 20 秒（Apple Silicon、常駐ありで 18 秒）。律速は声の生成。続けて作る時は `make_confirm.py serve` で常駐させる
- 終了コード 2（照合で要確認）の時は `<名前>.work/asr.json` を見て `say` を直して作り直す。照合は「原稿どおりに聞こえるか」の機械判定で、自然さは見ていない。聴いていなければ「未聴」と伝える
- 長い原稿を一括で音声にしない（後半が崩れることがある）。必ず発話ごとに作る
- 動画を作れない時に字幕だけで済ませず、短く障害を伝える

## チャットに出す（AGI Cockpit の Crew の場合）
- 動画を添付し、選択肢をボタンにして返信する:
  `cockpit crew reply --message <id> --file confirm.mp4 --button "go:success=✅ そう" --button "redo:primary=🔄 ちがう（声で）" --pressable-by owner --stdin`
- 押されると `button_id` 付きのメッセージとして届く。押された投稿は `cockpit crew edit --message <id> --no-buttons --stdin` でボタンを外し、「誰が何を選んだか」を書き足す
- 本文の長さに上限は設けない。動画と同じことを長々と繰り返さず、判断に要ることは文章でも書く
- ほかのチャット環境では、その環境のボタン（またはリアクション）で同じ形にする。押した人と選択を確かめられない経路では、投票から自動で実行しない

## チャットに出す（Claude Code の場合）
- 道具の場所: `tool/` はリポジトリの直下にある。スキルを symlink で置いた場合は `readlink ~/.claude/skills/dui` の 1 つ上がリポジトリ（例: `~/product/dui/tool/make_confirm.py`）。`python` と Irodori の場所は `tool/config.json` に従う
- 動画を作ったら `open <mp4>` で開く（QuickTime）。返信には動画のパスも書く
- 選択肢は **選択肢ダイアログ（AskUserQuestion）** で聞く。台本の最後の `question` の `choices` を、`label` はそのまま、`action` を説明文にして並べる。追加の注文は「その他」への記入か音声入力で受ける
- 目の前の本人だけが押せるので、押した人の確認（`--pressable-by`・`scripts/resolve_reaction.py`）は使わない
- 声は Irodori-TTS（速さ・無料を優先した確認用）。お客様に見せる動画は DUI で作らず、別の手段（Gemini TTS など）で作る

## 選ばれた範囲だけ動く
- 票は実行内容の指定であって、権限の拡張ではない。外部公開・削除・課金など、必要な承認は省略しない
- 本人の停止・変更の指示は、ボタンより優先する
- 押した人が判断してよい人かを確かめてから動く（`--pressable-by` で絞る）

## 溜まった動画を消す
- `tool/cleanup.py` で、出力フォルダ直下の 3 日より古い確認用動画と中間ファイルを消す（名前に keep を含むもの・keep.txt に載せたものは残す）。まず `--dry-run`
- 毎日の実行は、launchd（`tool/schedule/dui-cleanup.plist.example`）か、Cockpit の Autorun で登録する
